# Pinned Unicode CLDR data

These unmodified English annotation files come from **CLDR 48.2**, tag
`release-48-2` in Unicode's official repository:

| Local file | Upstream file | SHA-256 |
| --- | --- | --- |
| `en.xml` | [common/annotations/en.xml](https://github.com/unicode-org/cldr/blob/release-48-2/common/annotations/en.xml) | `8511aadd046fdba2f0ffe590266ced8bbf48175ad139b2675d85d7141057b235` |
| `en-derived.xml` | [common/annotationsDerived/en.xml](https://github.com/unicode-org/cldr/blob/release-48-2/common/annotationsDerived/en.xml) | `d76bd041c8c9e7b00b716aff8b7d9dbf509877010e191d5efd068be2553e066e` |

The snapshot includes emoji, sequences, and other annotated symbols. `type="tts"`
provides descriptive names; other annotations provide keywords separated by `|`.
CLDR omits U+FE0F emoji presentation selectors from its keys. Runtime lookups do
the same without changing the input returned for an unknown value.

From the repository root, regenerate the checked-in Go tables with:

```sh
task generate-cldr
```

The task runs `go generate ./...`, which can also be invoked directly.
Generation verifies the source checksums and uses no network. Ordinary builds
use `metadata_generated.go`; they do not read XML or run the generator. The test
suite checks that generated output exactly matches the pinned snapshot.

To update, select a published CLDR release, download the two files and its
`LICENSE`, update the release in `internal/cmd/gencldr/main.go`, hashes in
`sources.json`, and this document, regenerate, and run `task ci`. Review changes to names and keywords.
Additional pinned annotation/derived pairs for `de`, `es`, `fr`, `ja`, and `zh`
are listed alongside English with SHA-256 hashes in [sources.json](sources.json). Their upstream
paths are `common/annotations/{locale}.xml` and
`common/annotationsDerived/{locale}.xml` at the same `release-48-2` tag. Local
`{locale}-derived.xml` files correspond to the latter. `zh` is Simplified Chinese.
Generation emits these translations in `locales_generated.go` and checks every
source checksum and language identity. All files are unmodified upstream XML.

To add a base language, download both files, add their hashes and locale to the
manifest, regenerate, and test. The extractor rejects unresolved inheritance
markers and incomplete names; region/script data needing inheritance resolution
are explicitly rejected; they must not be added as though they were complete
base-language tables. Runtime
lookup uses a limited bundle matcher with English fallback, not full CLDR locale
inheritance. Missing localized entries fall back to English; missing keywords
use the localized name. See the public locale API documentation for matching.

## Emoji sequence classification

`emoji-test.txt` is the unmodified [Unicode Emoji 17.0 test data](https://unicode.org/Public/17.0.0/emoji/emoji-test.txt).
SHA-256: `1d8a944f88d7952f7ef7c5167fef3c67995bcae24543949710231b03a201acda`.
The generator verifies this digest and extracts fully-qualified sequences and
the nine named hair/skin-tone components into
`emoji_sequences_generated.go`. Text conversion uses that table to distinguish
emoji from the non-emoji symbols also present in CLDR annotations and to choose
canonical emoji presentation on reverse conversion. It is regenerated by the
same `task generate-cldr` command and covered by Unicode License v3.
